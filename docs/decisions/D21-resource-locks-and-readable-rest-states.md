# D21؛ قفل هر منبع و نمایش وضعیت REST

تاریخ: ۲۰۲۶-۱۰-۰۹. این تصمیم جایگزین بخش قفل سراسری D11/D18 می‌شود.

## قفل‌های تراکنشی

هر تغییر Mission ابتدا قفل همان Mission را می‌گیرد و سپس وضعیت واقعی را
می‌خواند. اگر منابع فعال دارد، قفل راننده و سپس خودرو گرفته می‌شود. Assign
از Scheduled نیز پیش از خواندن eligibility، همین ترتیب راننده/خودرو را رعایت
می‌کند. Fleet فقط قفل خودروی مورد تغییر را می‌گیرد. ثبت خودروی تازه یا رانندهٔ
تازه قفل منابع موجود را نمی‌گیرد؛ یکتایی پلاک همچنان constraint دیتابیس دارد.

قفل advisory تا commit/rollback آزاد نمی‌شود. کلید، ۶۴ بیت نخست SHA-256 رشتهٔ
`fleet:{scope}:{id:D}` با ترتیب بایت big-endian است؛ همهٔ instanceها و سیستم‌عامل‌ها
کلید یکسان می‌سازند. scopeهای mission/driver/vehicle مستقل‌اند. برخورد hash ممکن
است دو منبع مستقل را به‌ندرت سری کند، ولی اجازهٔ تخصیص دوگانه ایجاد نمی‌کند.

ترتیب ثابت Mission سپس Driver سپس Vehicle، از گرفتن معکوس منابع جلوگیری می‌کند.
تخصیص مجدد Assigned طبق قاعدهٔ موجود پیش از گرفتن منابع جدید رد می‌شود؛ همان
دو شناسه همچنان no-op است. Fleet هیچ قفل Mission یا Driver نمی‌گیرد، بنابراین
چرخهٔ Vehicle → Mission ایجاد نمی‌کند. قفل‌های DB و unique indexهای رزرو آخرین
حفاظت صحت‌اند؛ شکست commit نیز به Conflict نگاشت می‌شود.

شمارندهٔ نسخهٔ کش همچنان یک ردیف DB است و فقط تغییر membership دسترس‌پذیری
آن را افزایش می‌دهد. نوشتن‌های مرتبط ممکن است هنگام افزایش نسخه کوتاه‌مدت
صف شوند؛ ادعای حذف تمام contention نداریم. دو خواندن کوچک نسخه در cache hit
برای تشخیص تغییر هنگام خواندن حفظ شده‌اند. حذف آن‌ها بدون پروتکل انتشار پس
از commit می‌تواند snapshot کهنه را پنهان کند. Assign همچنان از کش تصمیم نمی‌گیرد.

تست‌ها: رقابت هشت تخصیص، تخصیص/تعمیر، تغییر نسخه و استقلال منابع در
`AvailabilityOptimizationTests` و `OperationsAcceptanceTests`.

## قرارداد وضعیت‌ها

REST وضعیت‌های کسب‌وکار را به نام enum می‌دهد: مثلاً `baseStatus: "Active"`
و `status: "Assigned"`. JsonStringEnumConverter برای چهار enum محصول ثبت شده؛
کد عددی ورودی قدیمی نیز پذیرفته و مقدار نامعتبر توسط validation رد می‌شود.
عدد outcome در Audit و کدهای HTTP تغییر نکرده‌اند. فیلدهای افزودهٔ `*Name` حذف
نشده‌اند. gRPC همچنان enumهای proto با field numberهای ثابت دارد.

این تغییر برای کلاینتی که در پاسخ REST عدد انتظار دارد شکستن قرارداد است؛
کلاینت Smoke، آزمون‌های برابری REST/gRPC و انتظارهای Postman به نام‌ها تغییر
کرده‌اند. README قرارداد جدید را بیان می‌کند. نسخهٔ تحویل هنوز منتشر نشده
است؛ مصرف‌کنندهٔ قبلی باید پیش از استفاده از نسخهٔ اصلاح‌شده به‌روز شود.

Driver اکنون GET با شناسه و پاسخ 201 همراه Location دارد؛ عملیات وضعیت و تعمیر
خودرو view کامل و به‌روز برمی‌گردانند. authorization همان ماتریس نقش‌هاست.
